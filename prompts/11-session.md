ROADMAP.md 1~4단계에서 세션마다 보내는 지시문입니다. 한 세션에 작업 묶음 하나만 맡깁니다. 대괄호 세 곳을 채워 붙여 넣고, 자리를 비울 거면 이어서 `goal.md`의 한 줄을 입력합니다.

- 단계: ROADMAP.md 진행 상태 표에서 '진행 중'인 단계의 번호입니다.
- 작업 묶음: 그 단계의 묶음 하나를 ROADMAP.md에 적힌 그대로 넣습니다.
- 통과 기준: 화면을 바꾸는 1~2단계는 첫째 줄을, 동작과 마감을 다루는 3~4단계는 둘째 줄을 넣습니다.
  - `npm run ab에서 새 빌드 선호가 70% 이상이다`
  - `이번 세션에서 먼저 만든 검사가 모두 통과한다`
- 검사로 확인할 수 없는 묶음은 대화에 드러나는 결과로 고쳐 씁니다. 예: `README.md가 커밋돼 있고 npm run check가 통과한다`

```
ROADMAP.md [1]단계에서 작업 묶음 하나를 이번 세션에 끝내 줘. 일하는 방식은 CLAUDE.md와 docs/evaluation.md를 따른다.

- 이번 작업 묶음: [① 그림자와 간접 차폐]
- 통과 기준: [npm run ab에서 새 빌드 선호가 70% 이상이다]
- 시작하면 PROGRESS.md에 세션 시작 시각, 작업 묶음, 통과 기준을 적어. 화면을 바꾸는 묶음이면 수정하기 전에 지금 빌드를 기준선으로 저장해.
- 고치기 전에 원인부터 적어. BACKLOG.md에서 이 묶음에 해당하는 지적이 왜 반복됐는지, 어떤 도구나 구조를 바꾸면 한꺼번에 없어지는지를 PROGRESS.md에 쓴 다음 구현해.
- 동작을 고치는 묶음이면 고치기 전에 그 문제를 재현하는 검사부터 만들어. 지금은 실패하고 고친 뒤에는 통과해야 한다.
- 한 장면만 손보지 말고 레벨 전체에 적용되는 방식으로 만들어. A/B는 npm run shots가 찍는 모든 장면을 비교한다.
- 통과 기준에 못 미치면 같은 수정을 더 쌓지 말고 접근을 바꿔. 점수나 비율이 오르지 않는다는 이유로 마감하지 마.
- npm run check 통과와 SPEC.md의 성능 목표는 계속 지켜.
- 나는 자리를 비운다. 결정이 필요하면 가장 합리적인 쪽을 골라 PROGRESS.md에 이유를 적고 계속해.

끝나면 npm run check 출력, 성능 측정값, 통과 기준을 확인한 명령 출력, git log를 대화에 보여 주고 SPEC.md 형식의 마지막 보고를 써. 전후 시트와 측정값 요약은 docs/shots/에 커밋하고, 남은 지적은 BACKLOG.md에 반영해.
```

세션이 끝나면 docs/shots/의 전후 시트를 확인하고 직접 플레이합니다. 다음 묶음으로 넘어갈지는 그 뒤에 정합니다.

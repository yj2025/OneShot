ROADMAP.md 0단계(측정 정비)의 지시문입니다. 기준선 수치를 보고 통과 기준을 정하는 세션이라 옆에서 지켜보고, `/goal`은 걸지 않습니다.

보내기 전에 확인합니다.
- `refs/`에 레퍼런스 프레임이 6장 이상 있습니다. 고르는 기준은 `refs/README.md`에 있습니다.
- Claude Code를 레포 루트에서 시작했고 `/agents` 목록에 critic과 ab-judge가 보입니다.
- 10분 플레이하고 거슬리는 점을 PLAYTEST.md에 적었습니다. 없어도 진행됩니다.

아래 블록을 그대로 붙여 넣습니다.

```
이번 세션은 ROADMAP.md의 0단계다. 게임 화면은 바꾸지 않는다. 평가 도구를 고치고 기준선을 재는 세션이다. 지난 14라운드는 레퍼런스 없이 채점해서 점수가 1~2점씩 흔들렸고, 지적 하나에 수정 하나로 대응하다가 3~5점에서 멈췄다. 같은 일이 반복되지 않게 하는 것이 목적이다. 절차와 도구 요구사항은 docs/evaluation.md에 있다.

1. 먼저 확인한다. refs/에 이미지가 6장 이상 있는지, critic과 ab-judge가 서브에이전트로 등록되어 있는지 본다. 하나라도 아니면 아무것도 고치지 말고 그 사실을 알려 준 뒤 멈춘다. 기준선을 재는 세션이라 이번에는 범용 서브에이전트로 대신하지 않는다.
2. PROGRESS.md에 세션 시작 시각과 '0단계 측정 정비'를 적는다.
3. npm run ab를 docs/evaluation.md의 요구사항대로 만든다.
4. 영점을 확인한다. 같은 빌드를 두 번 찍어 서로 비교하고, 한쪽으로 쏠리면 원인을 찾아 고친다.
5. 기준선을 잰다. 레퍼런스를 섞은 비교 시트를 critic 3명에게 따로 보내 식별 정답률, 점수 중앙값, 세 점수의 차이를 CRITIC_LOG.md에 적는다.
6. BACKLOG.md를 검토한다. CRITIC_LOG.md와 소스를 대조해 틀린 분류나 사실을 고치고, PLAYTEST.md에 적힌 지적과 5번에서 새로 나온 지적을 넣는다.
7. 빌드 화면만 모은 시트와 측정값 요약을 docs/shots/baseline/에 커밋한다. 레퍼런스가 들어간 이미지는 커밋하지 않는다.

끝나면 npm run check 출력, 영점 확인 결과, 기준선 수치, BACKLOG.md에서 고친 점을 대화에 보여 줘. 그 수치로 볼 때 ROADMAP.md의 A/B 선호 [70]%가 통과 기준으로 적절한지 네 의견을 PROGRESS.md에 제안으로 적고 대화에도 알려 줘.
```

끝나면 기준선 수치와 Claude의 의견을 보고 ROADMAP.md의 대괄호 값을 확정합니다. 0단계를 통과로 판단하면 ROADMAP.md 진행 상태 표에서 0단계를 '통과', 1단계를 '진행 중'으로 고칩니다.

## 2. 이 계획이 따르는 것
1. 한 세션에 작업 묶음 하나. 시간 상한 4시간.
2. 지적마다 작은 수정을 붙이지 않고, 같은 지적을 만드는 도구나 구조를 고친다. 두 지적의 원인이 같으면 한 도구로 같이 고친다(아래 '묶어서 고칠 것').
3. 통과는 A/B 부호 검정(갈린 쌍 5개 이상, p ≤ 0.05)으로 판단한다. 화면 일부만 바꾸는 묶음은 처음부터 확대 쌍을 함께 받는다.
4. 2단계가 통과할 때까지 새 기능을 더하지 않는다(리뷰 권고, user-edits.md 1.7절).
5. 동작을 고치는 묶음(3단계)은 문제를 재현하는 검사를 먼저 만든다.

### 3.1 세션 1: 2단계 ③ 재개 — 손과 소매의 형상, 총의 마모
- 지적: 위 1절의 가장 큰 격차. BACKLOG.md '총과 손'.
- 구조 후보
  - **천 형상 도구**: 소매를 원통에서, 팔꿈치와 손목에 몰리는 주름, 솔기, 소맷부리 단을 가진 메시로 바꾼다. 같은 도구를 2단계 ①(봇의 옷 주름)에도 쓴다.
  - **장갑**: hands.js의 거리장 장갑에 마디 덧댐과 손등 패드의 부피, 봉제선, 손가락 사이 틈을 형상으로 넣는다. 재질 표에 손바닥과 덧댐의 반사율을 따로 적으면 검사 (l)의 장갑 허용 폭을 20%로 좁힐 수 있다.
  - **총의 마모**: 닳은 모서리(materials.js markEdges)를 넘어서, 손이 닿는 자리의 광택, 긁힌 자국, 먼지가 끼는 틈을 부품의 형상에서 계산해 넣는다.
- 평가: 시작에 critic 3명, 중간과 끝에 A/B(좌우 교차, 판정자 4명). 장면마다 총과 손을 확대한 쌍을 함께 받는다.
- 통과 기준: A/B 부호 검정 p ≤ 0.05(갈린 쌍 5개 이상), check 통과, 성능 목표 유지.
- 끝난 뒤 사용자 결정: critic 1순위가 그대로 총과 손의 형상이면, 뷰모델을 '전부 코드로' 조건의 예외로 둘지 정한다(user-edits.md 2.3절).
- 결과(2026-11-17 08:28~10:15): A/B 57(확대 쌍) 23–0–8, p = 1.2e-7로 통과 기준 충족. critic 38의 1순위는 셋 모두 여전히 손과 소매(손가락 마디 없는 장갑, 받침손 소매)다. 위 사용자 결정이 필요하다.

### 3.2 세션 2: 2단계 ④ — 연사 때의 화면 반동과 총구 화염, 걸을 때의 총
- 지적: 연사 반동이 같은 모양으로 되풀이된다(19번), 걷는 동안 총이 화면 오른쪽 아래에 붙어 있다(critic 모두, 맡은 묶음 없음).
- **묶어서 고칠 것**: 두 지적의 원인이 같다. 총의 화면 위치가 카메라에 붙은 스프링 몇 개(player.js camRecoil, weapons.js recoilT·recoilR)로만 움직인다. 팔과 몸에 들린 질량으로 총을 움직이는 한 모형(발마다 다른 충격, 걸음의 충격, 숨, 손떨림)으로 바꾸면 반동과 걸음이 함께 고쳐진다. 그래서 '걸을 때의 총'을 이 묶음에 넣기를 제안한다.
- 먼저 만들 검사: 연사 두 발의 화면 궤적이 겹치지 않는다(상관 상한), 걷는 1초 동안 총의 화면 위치가 움직인다(이동 하한).
- 함께 다시 지을 자리(2026-11-17 세션 1에서 찾음): 소총 받침손은 왼쪽 어깨에서 0.69~0.79 m라 사람 팔(0.58 m + 어깨 12 cm)로 닿지 않는다. 권총은 두 손을 가슴 앞에 모아 두 팔뚝이 렌즈 0.21~0.23 m 앞을 지난다. 두 자리 모두 지금은 이전 방식의 긴 팔뚝으로 그린다. 총을 드는 자세를 어깨에서 닿는 자리로 옮기면 두 마디 팔(weapons.js solveArm)이 그대로 쓰인다.

### 3.3 세션 3, 4: 2단계 ①과 ② — 봇의 몸과 움직임
- 지적: 짙은 회색 마네킹, 막대 팔다리, 굳은 자세(12번).
- 지금 구현: 관절 15개 사이에 원뿔대와 둥근 상자를 놓은 인형이다.
- 구조 후보: 장갑에 쓴 거리장 메시 도구로 몸을 한 덩어리 메시로 짓고, 세션 1의 천 형상 도구로 옷 주름을, 장비(조끼, 탄입대, 헬멧 커버)는 형상 도구로 붙인다. ②는 걸음, 피격, 쓰러짐 동작이다.
- 통과 기준에 사용자가 가까이서 보는 판정이 들어 있다.

## 5. 위험과 대응
- **형상을 고쳐도 critic 점수가 움직이지 않는다**: 뷰모델은 모든 칸의 전경이라 다른 진척을 가린다. 세션 1 뒤에 사용자 결정(3.1절 끝).
- **A/B 판정 불가**: 화면 일부만 바뀌면 갈린 쌍이 5개에 못 미친다. 확대 쌍을 처음부터 함께 받는다.
- **끝 평가를 여러 번 받아 우연히 통과**: 최종 빌드의 끝 평가 한 라운드만 통과로 친다(docs/evaluation.md).
- **성능 여유가 준다**: 세션마다 `npm run perf`. 새 효과는 낮은 품질에서 끌 수 있게 둔다.
- **범위가 다시 는다**: 2단계 통과 전에는 기능을 더하지 않는다.

```bash
npm install
```
```bash
npm run build
```

```bash
npm run dev
```


## 5. 평가 체계 (자세히는 docs/evaluation.md)
- **critic**(서브에이전트 3명): 빌드 화면 11칸과 레퍼런스 8칸을 섞은 시트에서 빌드를 가려내고 10점 만점으로 점수를 매긴다. 추세를 보는 용도다.
- **ab-judge**(서브에이전트 4명): 기준선 대 새 빌드 31쌍에서 더 실제 같은 쪽을 고른다. 좌우를 바꾼 시트 두 벌을 2명씩 본다. 두 벌 모두에서 같은 빌드가 고른 쌍만 승패로 세고, 갈린 쌍의 부호 검정으로 진척을 판단한다. 갈린 쌍이 5개 미만이면 바꾼 부분을 확대한 쌍으로 다시 받는다.
- 판정자에게는 파일 경로만 넘긴다. 코드, 과정, 이전 결과는 넘기지 않는다. 정답 키(out/keys/)는 채점 도구만 연다.
- refs/(레퍼런스 이미지)와 out/(촬영, 시트, 키, 기준선)은 커밋하지 않는다. 기준선을 잃으면 그 커밋의 dist를 꺼내 다시 찍는다.
- 화면이 아닌 동작을 고칠 때는 그 문제를 재현하는 검사를 먼저 만들고, 고치기 전 빌드에서 실패하는 것을 확인한다.

## 6. 열린 문제 (우선순위 순, 자세히는 BACKLOG.md)
1. **총과 손의 형상**: 16~35라운드에서 critic 모두가 꼽은 가장 큰 격차다. 소매가 주름 없는 원통이고, 장갑은 손가락 없는 덩어리이고, 총 표면에 긁힘과 마모가 없다. → 2단계 ③을 다시 연다.
2. **연사 때의 화면 반동**: 19번 지적됐다. 두 발의 반동이 같은 모양으로 되풀이된다. → 2단계 ④
3. **봇**: 12번 지적됐다(마네킹 같은 몸과 동작). → 2단계 ①, ②
4. **걷는 동안 총이 화면에 붙어 있다**: 최근 critic 모두가 적는다. 맡을 묶음이 정해지지 않았다.
5. **성능 끊김**: 최악 프레임이 30~40 ms다. 측정 때마다 흔들린다. → 4단계 ①
6. **바깥 재질의 반사율**: 실제의 절반쯤이다. 이 때문에 반사 프로브를 건물 밖에서 끈다.
7. **소리**: 총성의 음색, 탄피와 발소리의 음색. ROADMAP에 소리 묶음이 없다.

## 9. 실제로 겪은 함정
- `git checkout -- <파일>`은 커밋하지 않은 수정까지 지운다. 실험을 되돌릴 때는 그 부분만 고친다.
- 줄 끝이 섞여 있다. src/materials.js는 CRLF이고 나머지는 대개 LF다. 스크립트로 고칠 때 원래 줄 끝을 지킨다.
- check나 shots가 도는 동안 build를 하지 않는다. critic이 out/perf.json을 읽는 동안 perf를 돌리지 않는다.
- 같은 기기에서 다른 3D 게임이 돌면 성능과 실시간 검사(걷기와 달리기 구분)가 흔들린다. GPU 사용률을 함께 적는다.
- 헤드리스 Chromium이 소프트웨어 렌더러로 떨어지면 수치가 무의미하다. 렌더러 이름(ANGLE D3D11 RTX 5060 Ti)을 확인한다.
- 키는 event.code로 읽는다(한글 입력 상태 대응). 포인터 잠금과 오디오는 사용자 입력이 필요해 자동 플레이는 `?test=1`로 들어간다.
- 시각을 적기 전에 `date`를 돌린다. 세션 사이에 빈 시간이 생긴다.

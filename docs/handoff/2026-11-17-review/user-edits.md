## 1. ROADMAP.md

### 1.1 통과 기준 문구
'단계' 표의 1단계와 2단계 통과 기준을 바꾼다.

- 지금(1단계): 묶음마다 A/B에서 새 빌드 선호 [70]% 이상, check 통과, 성능 목표 유지
- 바꿈(1단계): 묶음마다 A/B 부호 검정 p [0.05] 이하(갈린 쌍 [5]개 이상), check 통과, 성능 목표 유지
- 지금(2단계): 묶음마다 A/B [70]% 이상, 내가 가까이서 봐도 봇이 마네킹으로 보이지 않는다
- 바꿈(2단계): 묶음마다 A/B 부호 검정 p [0.05] 이하(갈린 쌍 [5]개 이상), 내가 가까이서 봐도 손과 봇이 마네킹으로 보이지 않는다

'내가 맡는 일' 표의 0단계에 있는 "기준선 수치를 보고 [70]% 확정"은 "영점 확인과 다시 채점한 표를 보고 [0.05]와 [5] 확정"으로 바꾼다.

### 1.2 2단계 묶음과 순서
번호는 그대로 둔다. 기록과 BACKLOG.md가 '2단계 ③'처럼 번호로 가리키기 때문이다.

- 지금: ① 봇의 몸 형태, 옷 주름, 장비 흔들림 ② 걸음·피격·쓰러짐 동작 ③ 손과 총 디테일 ④ 연사 때의 화면 반동과 총구 화염
- 바꿈: ① 봇의 몸 형태, 옷 주름, 장비 흔들림 ② 걸음·피격·쓰러짐 동작 ③ 손과 소매의 형상, 총의 마모 ④ 총의 움직임: 연사 때의 화면 반동, 걷는 동안 총의 흔들림, 총구 화염

④에 '걷는 동안 총의 흔들림'을 넣은 것은 핸드오프의 열린 문제 4번(걷는 동안 총이 화면에 붙어 있다)을 맡을 묶음이 없기 때문이다.

## 2. SPEC.md

### 2.1 범위
지금 문장은 부착물을 만들지 않는다고 한다. 소총 4배 조준경을 두기로 했다면 이렇게 고친다.

- 지금: 범위는 여기까지다. 맵 1개, 모드 1개만 만든다. 멀티플레이, 성장 요소, 부착물, 드론, 차량은 만들지 않는다. 남는 시간은 전부 완성도에 쓴다.
- 바꿈: 범위는 여기까지다. 맵 1개, 모드 1개만 만든다. 부착물은 소총의 4배 조준경 하나만 둔다. 멀티플레이, 성장 요소, 그 밖의 부착물, 드론, 차량은 만들지 않는다. 남는 시간은 전부 완성도에 쓴다.

### 2.2 조작
- 지금: 조작: WASD 이동, 마우스 조준, 좌클릭 발사, 우클릭 조준, R 재장전, Shift 달리기, C 앉기, Esc 일시정지.
- 바꿈: 조작: WASD 이동, 마우스 조준, 좌클릭 발사, 우클릭 조준, R 재장전, Shift 달리기, C 앉기, Space 점프(두 번 누르면 파쿠르), Esc 일시정지.

### 2.3 뷰모델을 '전부 코드로' 조건의 예외로 둘지
지금 정하지 않는다. 2단계 ③을 다시 돌린 뒤에도 critic의 1순위가 총과 손의 형상이면 정한다.

해당 문장: 모델, 텍스처, 소리는 전부 코드로 만든다. 이미지, 3D 모델, 오디오 파일은 내려받지도 포함하지도 않는다. 어디서든 재현되고 저작권 문제가 없게 하기 위해서다.

- 유지한다: 손과 소매와 총을 계속 코드로 만든다. 2단계 ③에 세션을 더 쓴다. 프로젝트의 전제가 그대로 남는다.
- 예외를 둔다: 1인칭의 손, 소매, 총만 직접 만들었거나 사용 조건이 분명한 모델을 dist/index.html 안에 넣는다. 파일 하나로 실행되고 외부 요청이 없다는 조건은 지킨다. 문장이 지키려던 재현성과 저작권은 따로 관리해야 한다.

판단할 근거는 세 가지다. 2단계 ③을 다시 돌린 세션의 A/B 승패, critic의 '몸과 총' 점수가 시작과 끝에 어떻게 달라졌는지, 직접 본 화면이다.

'답하는 형식'
- 지금: 아래 일곱 줄로 답한다.
- 바꿈: 아래 여덟 줄로 답한다.
- '점수: N/10' 줄 다음에 한 줄을 더한다: `- 기준별 점수: 카메라 N, 렌즈와 센서 N, 빛과 공간 N, 몸과 총 N, 소리 N`

선택 사항으로, '기준'의 '몸과 총' 줄을 ab-judge.md와 맞출 수 있다.
- 지금: 몸과 총: 반복되지 않는 반동과 쓰러짐, 게임 UI 없음
- 바꿈: 몸과 총: 사람처럼 보이는 손과 몸과 자세, 반복되지 않는 반동과 쓰러짐, 게임 UI 없음

서브에이전트 파일은 세션을 시작할 때 읽힌다. 고친 뒤에는 새 세션을 연다. 답 형식이 바뀌면 그 앞뒤의 전체 점수는 조건이 달라 그대로 견줄 수 없다.

## 4. 검사 (l)
'가까운 바닥' 시점에서 총이 둘레의 0.55배이고 기준은 0.5다. 그래서 `npm run check`가 26/27이다. 셋 중 하나를 정한다.

1. **기준을 실효 반사율로 다시 쓴다(리뷰의 권고).** 지금 기준의 첫 조건은 뷰모델 밝기 ÷ 둘레 밝기다. 이 값은 등과의 거리에 따라 달라진다. 실내 핸드오프의 tools/look.mjs는 뷰모델의 실효 반사율도 이미 잰다. 뷰모델의 실효 반사율이 재질 표의 값에서 [20]% 안에 있는지, 레벨 재질의 반사율이 반사율 표의 범위 안에 있는지로 검사하면 거리와 무관해진다. 처음 문제였던 '둘레가 실제보다 어두워서 장비가 뜬다'는 둘째 조건이 잡는다.
2. **그 시점만 검사에서 뺀다.** 이유를 검사 옆에 적는다. 가장 빠르다. 그 시점에서 생기는 회귀는 보지 못하게 된다.
3. **그대로 둔다.** `npm run check`가 계속 실패한다. SPEC.md 완료 기준 1이 계속 미달이고 다른 회귀가 26/27에 묻힌다. 권하지 않는다.

# 검증 도구 요구사항

네가 화면을 보고, 플레이를 확인하고, 수치를 잴 수 있어야 무인 작업이 성립한다. 아래 도구를 게임보다 먼저 만든다. 구현 방법은 자유이고, 스크립트 이름과 출력 위치만 지킨다.

## 공통
- 화면은 가능하면 GPU가 켜진 실제 Chromium으로 그린다. 실행할 때마다 WebGL 렌더러 이름을 결과에 기록한다.
- 같은 입력이면 같은 화면이 나와야 한다. 난수 시드와 시작 위치를 고정할 수 있게 만든다.
- 테스트 전용 진입 경로를 둬서 포인터 잠금과 오디오 시작 단계를 지나간다. 일반 실행에는 영향을 주지 않는다.

## npm run shots
- 정해진 지점 6곳 이상과 플레이 중 장면을 찍는다. 플레이 중 장면에는 사격 순간, 피격 순간, 어두운 실내에서 밝은 곳으로 나가는 순간이 들어간다.
- 움직임은 연속 프레임 묶음으로 남긴다. 1초 동안 찍은 8장을 한 줄로 이어 붙인 이미지 한 장이다.
- 후처리와 녹화 표시까지 포함한 최종 화면을 그대로 찍는다.
- 저장 위치는 out/shots/다.

## npm run sheet
- 빌드 스크린샷과 refs/의 이미지를 같은 크기로 맞춰 한 장에 무작위 순서로 배치한다. 칸에는 A, B, C 같은 중립 이름만 붙인다.
- 시트는 out/sheets/round-N.png로 저장한다. 어느 칸이 빌드인지는 out/keys/round-N.json에만 적는다.
- 파일 이름, 칸 테두리, 해상도 차이로 출처가 드러나면 안 된다.
- refs/가 비어 있으면 빌드 화면만으로 시트를 만든다.

## npm run score
- 라운드 번호와, 비평가가 빌드라고 판정한 칸 목록을 인자로 받는다.
- 스크립트가 정답 키를 직접 열어 대조하고 정답률만 출력한다. 키 내용은 출력하지 않는다.

## npm run check
- SPEC.md 완료 기준 1번의 항목을 전부 검사한다. 하나라도 실패하면 0이 아닌 코드로 끝나고, 무엇이 실패했는지 출력한다.
- 자동 플레이는 실제 입력 이벤트로 조작한다. 내부 상태를 직접 바꿔서 통과시키지 않는다.

## npm run perf
- 정해진 경로를 30초 이상 돌면서 프레임 시간을 잰다.
- 평균, 95퍼센타일, 최악값, 렌더러 이름, 해상도, SPEC.md의 목표값을 out/perf.json에 적는다.
- 소프트웨어 렌더러에서 잰 값에는 참고용이라고 표시한다.

## npm run audio
- 총성(실내, 실외), 발소리(재질별), 재장전, 주변음을 오프라인으로 렌더링한다.
- 소리마다 길이, 최대 음량, 평균 음량, 클리핑 여부, 주파수 대역별 에너지를 out/audio.json에 적는다.
- 실내 총성의 울림이 실외보다 긴지, 재질별 발소리의 주파수 분포가 서로 다른지를 수치로 확인한다.
